Third-Party Iframes

Each iframe loads from its origin domain. Third-party cookies are written by those servers via Set-Cookie response headers — they appear under the origin domain (not this site) in DevTools → Application → Cookies. The scanner sees them via CDP Network.responseReceivedExtraInfo headers.

Scan Instructions

  1. Start local server: cd /path/to/cookie-consent-test-site && python3 -m http.server 3000
  2. Verify scanner can reach it: docker exec cookie-backend curl -s http://host.docker.internal:3000/all-trackers.html | grep title
  3. In the CMP UI, create a ConsentManager with website URL http://host.docker.internal:3000/all-trackers.html
  4. Click Start Scan — all cookies above should be detected within ~30 s
  5. Categories are resolved by OpenCookieDB → KnownServicesLibrary → "Others"

Notes

  • 4 iframes on this page (YouTube, Google Maps, Facebook, Bing Maps) — scan takes ~40-45 s vs ~25-30 s for a no-iframe page. Scanner warmup is 2 500 ms scrollIntoView + 500 ms mouseover per iframe.
  • Third-party cookies (YSC, NID, fr, MUID on bing.com, etc.) appear under their origin domain in DevTools, not under this site. The scanner captures them via CDP responseReceivedExtraInfo Set-Cookie headers.
  • _gcl_aw is a dummy inline cookie (correct GCL.<ts>.<gclid> format). The real path: reload with ?gclid=test123 — GTM Conversion Linker writes the real value.
  • th_capi_* are dummy Meta CAPI cookies (correct 64-hex SHA-256 format). Real CAPI cookies are written server-side by your backend; no browser script produces them.
  • MUID / ANONCHK / SRM_B only appear on the first scan from a fresh container IP (Clarity server-side deduplication). Restart the Docker container to get a fresh IP.
  • IDE (DoubleClick) does not appear — Google's ad SDK performs bot detection in headless; the auction never fires. Declare it via Manual API if needed.
  • Enforcement test: after scanning this page, go to enforcement-test.html with the generated cmid to verify blocking.
