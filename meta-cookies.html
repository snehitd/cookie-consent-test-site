About Meta Pixel & Facebook Advertising Cookies

Meta Pixel (formerly Facebook Pixel) is a JavaScript snippet — fbevents.js loaded from connect.facebook.net — that tracks user behaviour on your website and reports events (page views, add-to-cart, purchases, sign-ups, etc.) to Meta's advertising platform. This data powers ad attribution, custom audience creation, and conversion optimisation for Facebook and Instagram campaigns.

Facebook Ads uses Pixel data to measure which ads drove actions on your site, build lookalike audiences from converters, and enable dynamic product ads (showing users the exact products they viewed). Without the Pixel, advertisers lose visibility into post-click behaviour and cannot optimise bids for conversions.

Meta Conversions API (CAPI) is a server-to-server integration that sends event data directly from your backend to Meta, bypassing browser ad-blockers and ITP. It complements the Pixel by filling attribution gaps when the browser Pixel is blocked. CAPI events are matched to Meta users using hashed PII (email, phone, name).

Four ways Meta cookies get set on a website

  1. Meta Pixel — fbevents.js (first-party): The Pixel script writes _fbp as a first-party cookie on your domain on every page load. If the visitor arrived via a Meta ad (URL contains fbclid=), the Pixel also writes _fbc.
  2. Meta Conversions API — CAPI (first-party, server-side): After a conversion event (form submit, purchase, login), your server sends hashed PII to Meta's API. It simultaneously writes th_capi_em, th_capi_fn, th_capi_ln, th_capi_ph as first-party cookies. There is no browser script — this is purely server-side. On this test page these four cookies are simulated as dummies.
  3. Facebook Social Plugins (third-party via iframe): Embedding a Like button, Comments widget, or Share button loads an iframe from facebook.com. Facebook's servers set cookies like fr, datr, sb, locale, dpr, wd directly on the facebook.com domain. These are third-party cookies from your site's perspective and appear under facebook.com in DevTools, not your domain.
  4. Facebook Login & authenticated sessions (third-party): When a user logs into Facebook (or uses "Login with Facebook"), Meta sets xs (session authentication token) and c_user (Facebook user ID) on the facebook.com domain. These are only present when the browser has an active Facebook session.

Meta Pixel Consent Mode — Enforcement Reference

Meta Pixel exposes a consent API. On the enforcement branch, consent is revoked by default before the Pixel initialises, then granted or kept revoked based on the user's marketing consent choice.

Call When Effect Cookies Gated
fbq('consent','revoke') Before fbq('init',...) — default state Pixel loads but operates in Limited Data Use (LDU) mode — no personal data collected, no retargeting audiences built _fbp, _fbc, th_capi_*
fbq('consent','grant') After user accepts marketing consent Full tracking enabled — events, custom audiences, dynamic ads, conversion attribution all active All above unlocked

The Social Plugin iframe (Section C) third-party cookies (fr, datr, sb etc.) are gated by blocking the iframe element entirely until consent — the Pixel consent API does not control them. On the enforcement branch the iframe src is withheld until marketing consent is granted, then injected dynamically.
