About Bing Ads, UET & Microsoft Cookies

Microsoft Advertising (formerly Bing Ads) is Microsoft's paid search and display advertising platform. Ads appear on Bing, Yahoo, MSN, and the Microsoft Audience Network. Like Google Ads, it uses a tracking tag to measure conversions and build remarketing audiences.

Universal Event Tracking (UET) is Microsoft Advertising's equivalent of the Google Ads conversion tag. It loads bat.js from bat.bing.net, tracks user events (page views, custom events, purchases), and writes first-party cookies to persist visitor and session identities. A single UET tag covers all Microsoft Advertising campaigns — unlike Google Ads, there is no per-campaign tag.

Microsoft Clarity is a free behavioural analytics tool (heatmaps, session recordings, click maps). It is separate from Bing Ads but frequently deployed alongside UET. It writes its own first-party cookies (_clck, _clsk) and sends session data to clarity.microsoft.com. Consent categorisation: Analytics.

Microsoft / Bing third-party cookies are written by bing.com and microsoft.com servers when any Microsoft-hosted content loads on your page — such as a Bing Maps embed, a Microsoft SSO button, or a Bing search widget.

Three ways Microsoft / Bing cookies get set on a website

  1. Bing Ads UET tag (bat.js) — first-party: Include the UET snippet in <head> with your Tag ID. Cookies _uetsid, _uetvid, and MUID are written on first page load. _uetsid refreshes on each new session; _uetvid persists for 180 days across sessions. With enableAutoSpaTracking: true, UET also fires on SPA route changes without any extra code.
  2. Microsoft Clarity script — first-party: Embed the Clarity snippet (requires a Project ID from clarity.microsoft.com). Writes _clck (user ID, 1 year) and _clsk (session ID, 1 day). No ad account is needed — Clarity is free and independent of Microsoft Advertising.
  3. Microsoft-hosted content iframes — third-party: Embedding Bing Maps, a Microsoft SSO button, or any iframe from bing.com / microsoft.com causes those domains' servers to write cookies on their own domains. These are third-party cookies from your site's perspective and cannot be replicated with document.cookie.

Microsoft UET Consent Mode — Enforcement Reference

Microsoft UET supports a consent API via the uetq queue. On the enforcement branch, consent is denied by default before UET initialises, then updated based on the user's marketing consent.

Call When Effect Cookies Gated
uetq.push('set',{convConsentMode:false}) Before bat.js loads — default state UET loads but operates in consent-denied mode — conversion events not sent, no audience data collected _uetsid, _uetvid, MUID
uetq.push('set',{convConsentMode:true}) After user accepts marketing consent Full UET tracking enabled — events sent, remarketing audiences built, conversion attribution active All above unlocked

Microsoft Clarity does not have a native consent mode API. On the enforcement branch, Clarity is gated by blocking the script tag entirely until Analytics consent is granted (using type="text/plain" blocking). The Bing Maps iframe (Section C) third-party cookies are gated by withholding the iframe src until consent.
